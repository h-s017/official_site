# 香氛產品開發與報價管理

入口 `/admin/quotes/`。沿用官網登入、報價資料表及客戶頁，不新增另一套 MY ORGAN 資料庫。

## 資料與保護

`fragrance_quotes.cost_data.development` 保留產品、配方工作參照、原料採購／補貨、文件、決策、待確認、報價快照及操作紀錄。現有 `cost_data` 與 `public_data` 欄位不變，不需要資料庫 migration。

客戶版仍由原有 `read()` 明確建構 `public_data`。開發管理資料不加入該白名單。公開提案仍只讀 `fragrance_quote_public`。不改既有驗證、RLS 或圖片存取規則。

儲存會以原 `updated_at` 進行比較；更新衝突時不覆蓋，應匯出編輯內容後重新載入。操作紀錄為管理者介面記錄，並非不可竄改的法遵稽核紀錄。

## 使用流程

1. 選擇／新增報價案件，在上方「香氛產品開發管理」建立產品及來源參照。
2. 配方逐列填「實際加入香精 g」與同批「實際成品總重 g」。缺值不以滴數、比例或目標重量代替。此欄需為供應原品的實際 g；另行稀釋時先核對原品重量，不以稀釋液總重直接套用原品限值。
3. 手動確認產品用途、接觸部位、IFRA 類別與版本。相同 MY ORGAN ID（無 ID 則名稱及供應商）合併實際重量後比對，採最低填入限值；來源、版本、類別或證據狀態不足時不顯示肯定結論。
4. 完整安全評估、混合香精共有限制成分與天然原料拆解不在這個初步算式內。文件存在也不代表法規核准。
5. 在下方原有編輯器手動設定客戶與供應商數量、單價；新增「其餘個別化設計費」可與 LOGO、貼紙及視覺設計費分開記錄。
6. 「另存目前報價版本」保留不可在介面直接改寫的快照，支援並排比較與客戶摘要列印。各數量方案為替代方案，不加總為同一訂單。
7. 編輯資料由使用者按儲存後保留；只有明確點擊既有「儲存並發布客戶版」才更新公開內容，程式不自動送報價。

匯出／匯入支援本站備份及先前 HANA 開發站案件 JSON。匯入只更新未儲存的開發資料，保留當前原有報價欄位。MY ORGAN 參照匯入需附原始檔名、匯出日期與來源版本；匯入不宣稱已讀取使用者電腦 localStorage，不回寫 MY ORGAN 或 HANA OS。
